# /query

사용자 질문: **$ARGUMENTS**

## 🛡 0. 대전제

1. **답변의 근거는 `wiki/` 문서**. 기억·추측·웹 사전지식으로 때우지 않는다.
2. **모든 주장은 위키링크로 인용** — `[[경로/페이지명]]` 형태로.
3. **wiki가 부족하면 솔직하게** 고지하고, 들여올 소스 후보를 제안(갭 모드).
4. 답변이 **gold 가치**면 `Output/` 파일링을 제안해 탐색이 휘발되지 않게 한다.

## 🧭 1. 질문 유형 판단

| 유형 | 예시 | 답변 형태 |
|------|------|----------|
| 정의 | "function envy가 뭐야?" | 요약 + 위키 인용 |
| 비교 | "Zustand vs Jotai" | 비교 테이블 |
| 메커니즘 | "React는 왜 리렌더링해?" | 흐름 단계 |
| 추천 | "이 상황엔 뭘 써?" | 의사결정 플로우 |
| 로드맵 | "뭐부터 배워야 해?" | 순서 리스트 (1년 목표 참고) |
| 탐색 | "X랑 관련된 거 다 보여줘" | 위키링크 리스트 |

애매하면 **1회만** 사용자에게 확인.

## 🔎 2. Index-First 검색 (순서 엄수)

1. `wiki/index.md` 읽기 → 관련 카테고리·페이지 후보 특정.
2. `Grep` 으로 `wiki/` 전체에서 질문의 **핵심 용어** 검색.
3. 필요하면 `Glob` 으로 폴더 후보 탐색 — 도메인 기반이니 질문 주제에 맞는 폴더부터 (예: 인증 질문 → `wiki/security/**`, 렌더링 질문 → `wiki/browser/**` 또는 `wiki/react/**`, AI 관련 → `wiki/ai-native/**`).
4. 후보 **최대 5개** 선정 → **모두 Read**.
5. 참조 관계가 있으면(`[[...]]`) 그 링크 따라 1홉만 더 파고든다.

→ 페이지가 **하나도 안 잡히면 8. 갭 모드**로 분기.

## ✍️ 3. 답변 합성

- 주장마다 **위키링크 인용**. 근거 없는 문장 금지.
- 사용자의 **1년 목표 리스트** (sync/async, HTTP, 렌더링, React, Zustand, JS/Node 런타임, FE 아키텍처...) 와 연결되면 명시.
- **설명 가능성 기준** — "사용자가 30초로 설명 가능한 수준인가?" 자문하며 구조화.
- 낯선 용어가 답변에 들어오면 **짧은 정의**를 곁들인다.

## ⚠️ 4. 페이지 간 충돌 감지

답변 도중 페이지 A와 B가 모순되면 **둘 다 제시**하고:

```markdown
⚠️ [[페이지-A]] 는 X라고 하지만 [[페이지-B]] 는 Y. 확정 안 됨.
```

→ 다음 `/lint` 때 해결 대상으로 자동 올라감.

## 🎨 5. 답변 형태 분기

| 유형 | 형식 |
|------|------|
| 비교 | 마크다운 테이블 (축: 개념/사용처/API/장단점) |
| 로드맵 | 순서 리스트 + 각 단계의 선행/후속 지식 |
| 메커니즘 | 단계 블록 + (필요 시 mermaid 다이어그램) |
| 정의/추천/탐색 | 섹션 + 위키링크 리스트 |

## 📁 6. Gold 파일링 제안

답변이 의미 있는 크기·통찰이면 **마지막에** 묻는다:

> "이 답변, 어디 파일링할까?"
> - `Output/comparisons/` — 비교·대조
> - `Output/explanations/` — 설명자료 (1-pager)
> - `Output/roadmaps/` — 학습 로드맵
> - `wiki/concepts/` — 새 **개념 페이지로 승격** (wiki 본체)
> - 저장 안 함

승인 시 생성. 프론트매터 필수(`based_on:`, `created:`, `purpose:`), `wiki/index.md` 갱신.

## 🗂 7. 로그 (의미 있는 쿼리만)

매 쿼리마다 로그하면 소음. **사용자가 "기록해" 라고 할 때 or 파일링된 경우만** `wiki/log.md` 에:
```
## [YYYY-MM-DD] query | <질문 요약>
```

## 🕳 8. 갭 모드 (위키가 비거나 부족할 때)

1. **솔직 고지**: "위키에 이 주제 없음 / X만 있고 Y는 비었음."
2. 그 자리에서 **들여올 소스 후보 제시**:
   - 공식 문서 (MDN, react.dev 등 — 02 템플릿 트리거 참고)
   - 고품질 기술 블로그 후보
   - 관련 YouTube 강의
3. **"이 중 어느 걸 `raw/` 에 들일래?"** 물어보고 종료.

⛔ 위키 바깥 지식으로 답을 합성해 **가짜 근거**를 만들지 않는다. 꼭 필요하면 "일반 상식 기준으로" 라고 명시적으로 분리해서 말한다.
